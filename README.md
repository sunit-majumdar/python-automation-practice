# Three small Python automations: a report per city, 18 files into one, and a live weather call

> **Self-directed practice on a synthetic dataset.** Dabba Dash is a fictional delivery company. Every order row was generated by a script (see [dabba-dash-order-analysis](https://github.com/sunit-majumdar/dabba-dash-order-analysis)). Not affiliated with any real company. The weather data is a real live forecast, but it is not connected to the orders.

## In short

- Three automations in Python and pandas: one report per city, 18 monthly files combined into one table, and a live weather API call.
- Each was checked against a number I already knew: 15,000 orders and ₹5,969,716 of revenue, 18 files, and 42 weather rows (6 cities × 7 days).
- The weather data is practice only. It is not linked to the orders.

## What this is

Analysts repeat the same jobs again and again: the same report for each city, many files to combine, outside data to pull in. This repo shows three ways to let Python do the repeating. Each one ends with a check against a number I already knew.

## What I built

### 1. One report for every city
A function, `load_clean()`, repeats my cleaning steps in the same order every time. A second function, `city_report()`, builds a summary for one city. A loop runs it for all six cities and saves `city_report.csv`.

- **Check:** 15,000 orders and ₹5,969,716 of revenue (delivered orders only) match my earlier analysis.
- **A finding, and a wrong guess:** Bengaluru (27.6 min) and Mumbai (26.7 min) deliver slowest, against 22.2 min in Thane. I guessed longer distances. I tested it: average distance is about 3.0 to 3.1 km in every city, which explains less than half a minute of the 5.4-minute gap. The cause is not in this data.

### 2. Eighteen files into one
I split the orders into one file per month, then rebuilt the full table with a loop that finds the files (`glob`) and stacks them (`concat`). This is the pattern for monthly files that arrive from other teams.

- **Check:** 18 files, 15,000 rows, and the same revenue total as before. Nothing was lost or doubled.

### 3. A live API call
A function asks the free Open-Meteo weather service for a 7-day forecast for each city. It checks the reply, turns the JSON into a table, and a loop stacks the six cities into `city_weather.csv`.

- **Check:** status 200, and 42 rows (6 cities × 7 days).

## Caveats

- **The order data is synthetic.** Patterns come from a script, so this shows my method, not a real market.
- **The weather is not joined to the orders.** The order dates (2025 to mid-2026) do not overlap the forecast, so the third script shows the technique only.
- **The weather file is a snapshot** from 8 November 2026. Forecasts change daily, so a re-run gives different numbers. City coordinates are approximate.
- **I did not check the API's terms for commercial use.** This is personal practice.
